## 2024-05-15 - Optimize networkx graph traversal and cycle computation
**Learning:** In the `backend/app/services/financial_service.py` analysis logic, calling `list(nx.all_simple_paths(...))` fully materializes generators, leading to exponential memory and time consumption on dense financial transaction graphs. Similarly, unconditionally generating `list(nx.simple_cycles(...))` for every high-degree node creates an unnecessary $O(V+C)$ cost per node.
**Action:** Lazily evaluate generators using `itertools.islice()` when a limited number of results (e.g., top 5 paths) are needed. When an expensive generator output like `nx.simple_cycles` will be checked for multiple graph entities (like checking nodes in cycles), lazily evaluate and cache the result within the loop to reuse it across checks rather than unconditionally recomputing or generating it outside the loop when no entities meet processing thresholds.
