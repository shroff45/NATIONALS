## 2024-05-19 - NetworkX Lazy Evaluation Optimization
**Learning:** When using `networkx` generators like `nx.all_simple_paths` on dense graphs, materializing the entire generator into a list (e.g., `list(nx.all_simple_paths(...))`) can cause extreme memory consumption and $O(V+E)$ time complexity explosions even if only a few paths are needed. Furthermore, expensive graph operations like `nx.simple_cycles` inside loops (e.g., node iteration) cause redundant $O((V+E)*C)$ recalculations if not cached.
**Action:** Always use `itertools.islice` to lazily evaluate and slice `networkx` path generators instead of casting to `list`. Cache global graph properties like simple cycles outside of node iteration loops, or evaluate them lazily using the `if cycles is None:` pattern within the loop to prevent redundant computation.
